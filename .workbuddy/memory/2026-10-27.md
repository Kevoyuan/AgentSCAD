## 踩到的坑
1. **Bash grep 多分支 `\|` 静默失效**（本项目第 3 次）→ 普查一律用 Grep 工具。
2. **`resolveParameterSchema` 有 SCAD 回退**：写"无 schema"测试 fixture 时
   必须同时清掉 `scadSource`，否则组件渲染参数行而不是空态，断言全错。
   真实的 summary payload 也没有 `scadSource`——fixture 应该照抄真实载荷。
3. **测试文件扫描自己**：新验收测试正文里含 `'cyan-'` 字面量，
   扫描 `src/components` 时把 `__tests__` 也扫进去了 → 扫描器必须跳过 `__tests__`。
4. **`renderToStaticMarkup` 会把 `'` 转义成 `&#x27;`**：
   断言含撇号的句子要对 HTML 反转义后再 `toContain`。

## 顺手修的 housekeeping
- `.next-review/` 残留构建目录没被 `.gitignore` 命中（`/.next/` 只匹配精确目录名）。
  改成 `.next*/` 一族通配，ESLint 的 ignores 同样改成 `.next*/**`。
  残留目录已移到 `/Volumes/SSD/.agentscad-next-review-stale`。
- 教训同记忆里的 Tailwind 那条：**按名字列举忽略规则，下一个名字就会漏**。
- **`tsconfig.json` 也会被 Next 污染**：`next build` 会把当次 `distDir` 的
  `types/**/*.ts` 追加进 `include`。用一次性的目录名（`.next-review`）构建，
  就会多出一行；用两次就多两行，git diff 永远脏。
  **修法**：不要用一次性目录名。统一用 `.next-build`（生产）和 `.next`（dev），
  并把这两个名字的 glob 写进 `include`。验证方式：`cp tsconfig.json /tmp/before`
  → 构建 → `diff`。已验证 `.next-build` 构建后 tsconfig **零改动**。
