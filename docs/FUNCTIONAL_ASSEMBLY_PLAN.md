# AgentSCAD：功能装配体的完整目标与执行计划

版本：2026-10-29。状态：目标与执行计划；实现进行中，最终能力未验收。

本文整合本次任务的产品目标、证据边界、工程路线和验收方法。代码现状来自 `60720b8` 基础上的当前未提交工作区；文件存在不等于测试通过，也不等于已经上线。本次文档整理检查了代码，未重新运行完整测试、真实模型生成、浏览器端到端验证或实物实验。

## 1. 当前能力、证据边界与最终 Target

### 1.1 最终产品目标

**让用户用自然语言描述功能与约束，直接得到由完整、可识别、可单独制造或采购的零件组成的装配体；这些零件可以按说明装上、按说明拆下，并在明确的运动范围、材料、工艺、公差和使用条件下完成约定功能。每项能力都有与当前版本绑定的证据。**

“直接得到”指正常产品流程完成需求确认、生成、检查、必要修复和交付，不要求用户手工编写 SCAD 或装配 JSON。遇到未支持的机构、未知制造条件或验证不足，明确说明缺口并保留结果；不能悄悄删零件、降为外观模型或把未知写成通过。

目标同时覆盖单零件、多零件静态装配、可拆连接、传动机构和复杂子装配。铰链是第一个完整验证样例；复杂机构是后续正式验收范围。

用户提供的 [CADAM benchmarks](https://github.com/Adam-CAD/CADAM/tree/master/benchmarks) 和 [V8 示例](https://github.com/Adam-CAD/CADAM/blob/master/benchmarks/13-v8-engine.md) 是需求范围与可视表达的参照。V8 页面展示参数化模型、内部零件和运动参数，这些展示不能作为 AgentSCAD 装配、制造或功能通过的证据。目录页本次读取失败，不对其最新清单作完整性保证。

### 1.2 “function”必须写成可测试的合同

每个任务明确：输入是什么、输出是什么、工作范围、负载或其他边界、允许误差、寿命或循环次数、制造条件和失效判据。

| 机构/对象 | 最低功能定义 | 进一步声明所需证据 |
|---|---|---|
| 支架、旋钮、容器等单件 | 尺寸与接口满足要求；能完成安装或容纳任务 | 承载、强度、密封等分别测试 |
| 可拆铰链 | 在约定安装方向和约束下转动，能沿约定路径无损拆装 | 自锁、防脱、承载和寿命需要额外验证 |
| 螺母/螺栓、旋盖 | 螺纹匹配，可旋入旋出，达到指定行程 | 紧固扭矩、抗拔力、密封性另验 |
| 齿轮、行星机构 | 输入运动产生正确方向和比例的输出，指定范围内不卡死 | 额定扭矩、效率、磨损与噪声另验 |
| 单缸、径向或 V8 机构 | 输入轴驱动完整连杆/活塞关系，结构可装可拆 | 燃烧、热管理、润滑、功率不能由运动验证推得 |
| 叶轮、风扇、翼型、涡轮类 | 先区分几何样件、转动演示件与流体功能件 | 流量、压差、升力、效率和高速强度需要相应计算及实验 |

**首个复杂机构里程碑：可制造、可装拆、手动驱动的 V8 机械演示装配体。** 包含两列各四个气缸位置、八组活塞/连杆、曲轴、支承、所需连接件、可拆壳体与驱动接口；每个实例有身份。外观附件按已冻结需求交付，不能临时省略。发动机点火顺序不自动等于机械曲柄相位；相位、连杆布置和气缸偏置需要独立定义。实际燃油燃烧发动机属于另一个明确需求和验证等级，不在本里程碑内冒充完成。

### 1.3 每次交付应包含什么

1. 经确认的需求清单、功能条件、关键尺寸、未知项和假设。
2. 完整可编辑 SCAD；独立零件定义、实例、子装配、连接和坐标系。
3. 每个制造零件的独立文件，采购件的规格及数量；重复实例不能漏计。
4. 装配清单、单位、局部到装配坐标的变换、源文件与各产物的内容哈希。
5. 装配、拆卸顺序与路径，所需工具、夹持条件和可达空间。
6. 运动输入、范围、耦合关系、允许接触和碰撞报告。
7. 分层证据报告与原始日志；用户对具体版本的接受或拒绝记录。
8. 达到实物等级时附工艺记录、实测尺寸、装拆和功能实验记录。

展示剖切、爆炸图、装配位置和打印摆放是不同视图。制造文件必须保持完整零件；改变视图不应切掉实体或改变功能证据。

### 1.5 持续约束

- 所有新增业务实现、机构模型、测试案例和验证逻辑独立编写。不得复制或改写搬运 CADAM、其他 CAD 应用或零件库源码，也不把第三方源码作为生成上下文。
- 保留项目已有 OpenSCAD 运行时与既有依赖。任何新增第三方代码或库引入都单列决策，不借“参考实现”绕过用户约束。公共数学公式可独立实现并说明依据。
- 不通过硬编码某个 V8 或一组固定产品模板替代通用生成能力。手工原创样例用于验证工具；真实模型生成能力另测。
- 维持现有单件流程、SSE、状态、产物地址、参数提取、模型路由与计量契约。
- 本计划整理不启动付费模型实验、采购、打印或外部制造。后续先给出实验对象、预算上限、预期证据和停止条件。

## 2. 最重要的架构问题及因果链

以下优先级结合影响和证据强度；“判断”不是已执行实验结果。

### P0：需求声明、候选几何和验证真值尚未彻底分离

**事实：** 装配 JSON 可以由生成源提供；关节轴检查读声明；曲柄检查接受传入点；六层比较器不认证观测来源。相关代码见上表。

**因果链：** 模型提出关系 → 同一个模型提供期待值或观测 → 检查这些字段内部一致 → 错误几何可能获得看似可靠的报告。

**判断：** 若不建立独立冻结要求和实际产物测量，增加检查数量可能只增加错误信心。

**改动：** 分离 `RequirementContract`、`AssemblySpec`、`ArtifactSnapshot`、`Observation`、`ValidationReport`。要求来自用户确认与冻结测试；候选声明来自生成；测量由确定性工具或独立实验产生。报告必须绑定具体输入和产物版本。

### P0：零件可选择性与零件身份被混在一起

**事实：** [`part-identity-check.ts`](../src/lib/assembly/part-identity-check.ts) 用网格哈希、三角面摘要、包围盒判断差异及包含；没有使用实例变换。不同选择器得到相同网格被判失败。其结果仍保留“没有测量身份”的说明，但字段名可让上层误读。打包 README 有关于包含关系的固定陈述，而当前 [`bundle/route.ts`](../src/app/api/jobs/[id]/assembly/bundle/route.ts) 调用并未提供完整装配网格。

**因果链：** 不同字节/不同网格被当作不同零件 → 任意两个小方块可躲过差异检查；相同形状却不同材料的合法定义可能误报；局部坐标直接与世界包围盒比较可能误报；README 又可能超出实际证据。

**判断：** 这套检查适合作为异常筛查，不能成为语义身份通过条件。摘要相等也需要精确确认，不能当成无碰撞哈希或几何同一性证明。

**改动：** 把“选择器响应”“几何重复”“包围盒约束”“零件身份”“需求完整性”拆为不同断言；允许合法同形件；实例统一变换后再比较；导出说明由实际报告生成。优先加反例再改代码。

### P0：当前运动检查可被语法特征满足

**事实：** [`motion-contract.ts`](../src/lib/validation/motion-contract.ts) 的 M001 搜索运动意图词、角度赋值、三角函数、相位和剖切变量；不执行关节运动，也不测量碰撞。

**因果链：** 源码中有未使用的运动函数 → M001 可通过 → 用户可能把它理解为机构能动。主要依赖英文意图模式还会遗漏部分中文请求。

**改动：** M001 明确降为源码接口检查；用结构化功能意图决定所需验证层；实际改变输入、重新求值并提取几何/位姿，检查闭环、位移、方向、比例和碰撞。剖切是视图偏好，不是所有机构功能通过的必要条件。

### P1：测试合同可能与样例不一致，形成错误评价基准

**事实：** 原创铰链轴为 6 mm；孔采用 `6.4 / cos(180 / $fn)` 补偿多边形内切尺寸，源码名义直径间隙约 0.4 mm。独立 [`hinge-contract.json`](../scripts/eval/assembly-fixtures/hinge-contract.json) 的间隙范围为 0.1–0.3 mm，两者尚无明确绑定。

**判断：** 若直接把两者当同一基准，正确测量也可能得到失败；若事后改阈值追求通过，又会污染评估。

**改动：** 样例和要求分别版本化，冻结前决定是否属于同一案例；明确直径/半径间隙、几何误差与工艺误差。冻结后只能作为新的案例版本修改，并重跑旧版回归。

### P1：修复与视图变换可能改变功能，缺少跨阶段不变量

**事实：** 现有技能已增加完整零件及连接保留要求，见 [`scad-generation`](../skills/scad-generation/SKILL.md) 和 [`scad-repair`](../skills/scad-repair/SKILL.md)；这些仍是模型指令。主流水线会经历编译修复、验证修复和参数更新。

**判断：** 单靠提示无法确保修复后数量、轴线、间隙或功能范围保留；此风险需要错误注入证实，不能当成已经统计出的失败率。

**改动：** 每次改源后比较冻结要求，重新提取参数/装配声明，失效相关证据；约束关键实例数、连接、完整制造几何和工作范围。预算耗尽保留失败源与原因，不以删除必要零件获得“成功”。

### P1：整机网格检查与产品验收不足以表达装配成功

**事实：** 既有 [`component-check.ts`](../src/lib/validation/component-check.ts)、[`hole-check.ts`](../src/lib/validation/hole-check.ts) 和整机包围盒检查不携带完整装配语义；新界面仍以 JSON 编辑为基础。

**因果链：** 一个整体网格或多个连通分量 → 无法可靠还原制造件身份 → 无法逐件验收、定位干涉或说明拆卸 → 用户接受整个结果又可能被误记成工程功能通过。

**改动：** 单件检查与装配检查分开；有意接触及多实体规则由合同决定；界面提供零件树、关联高亮、连接和问题定位；验收事件绑定需求、源码、零件集合、验证报告及实物记录版本。

## 3. 最小机构案例：两件式可抽离铰链

### 3.1 冻结前的候选要求

本例选择轴与固定叶片一体、活动叶片带通孔的两件式铰链。它是一种可抽离的升降式连接。正常使用需要指定轴向保持条件，不能同时宣称“可直接抽离”和“任意方向自行防脱”。若用户需要自保持，则增加经过验证的保持结构或第三零件，并改变任务合同。

| 项目 | 候选合同 |
|---|---|
| 功能 | 固定叶片保持不动，活动叶片绕轴转动；沿 +Z 方向提起可拆卸 |
| 零件 | A：叶片与一体轴；B：带孔的活动叶片；两个制造零件、两个实例 |
| 坐标 | mm、右手系；Z 为轴方向；各件局部坐标独立，装配变换明确 |
| 源码名义尺寸 | 轴径 6 mm、有效高度约 12 mm；孔内切径约 6.4 mm、筒段高度 10 mm；以当前原创样例为候选，均待独立测量 |
| 间隙定义 | 名义直径间隙约 0.4 mm，名义径向间隙约 0.2 mm；最终验收范围在测量方案确定后冻结 |
| 转动范围 | -45° 至 +45°；非工作姿态也用于装拆路径检查 |
| 接触 | 仅允许声明的支承面/配合面接触；不能把整对零件加入无限制碰撞白名单 |
| 装拆 | 从 +Z 空间沿轴插入/拔出；确定起终位姿、行程、夹持点、工具及净空；路径必须测量 |
| 使用约束 | 低速、无外加工作负载的运动演示；轴向保持由明确安装条件提供，夹具进入测试环境模型 |
| 制造候选 | 分件 FDM 打印，材料、打印方向、机器和切片参数在实物实验前冻结；候选材料可为 PLA，不视为已验证 |

自由度要分状态表达：安装并受到轴向保持时验证约定转动；解除保持后允许轴向抽离。不能把可抽离连接在所有状态都简化成单一纯转动副。

### 3.2 端到端要完成的链路

1. **意图：** 保存原始请求与逐条要求，明确是否需要防脱、负载、制造方式和拆装次数。未决项影响哪一级验收要可见。
2. **生成：** 生成完整 SCAD，A/B 各有稳定模块和选择器；装配视图使用实例变换；不把 A/B 焊合成一个实体。
3. **身份：** 两个文件分别渲染；检测空输出、选择器忽略、错件、漏孔、额外碎片和重复整机。相同几何允许由合法定义或重复实例解释。
4. **导出与重建：** 用另一段独立读取流程加载导出包，验证哈希、单位、实例数及变换，复原装配。禁止靠原浏览器中残留状态“恢复成功”。
5. **配合：** 从实际几何测量孔、轴、端面、轴线和间隙，记录网格离散误差与算法误差；与冻结要求比较，不只读变量值。
6. **路径：** 对插入和拔出检查途中净空、前置拆卸、夹具及工具可达性。只检查起终点不够。
7. **运动：** 改变角度实际求值，检查 A 不动、B 围绕同一轴转动、轴距不漂移、形状不变、没有非允许碰撞。包含边界姿态与中间姿态。
8. **修复：** 注入孔缩小、错轴、错误旋转中心、参数未使用等缺陷；要求修复不得丢失零件、扩大许可范围或覆盖失败历史。
9. **实物：** 先打印校准试片，再按冻结工艺制造；独立人员测量与装拆；记录原始尺寸、力/扭矩、循环次数和破坏情况。
10. **验收：** 用户能分别决定数字结果是否满足任务、实物是否满足功能；两者有独立记录。

### 3.3 必须能识别的伪通过

| 伪通过方式 | 必须补充的反证检查 |
|---|---|
| 两个导出文件实际都是整机 | 选择器错误注入、独立几何对照、实例变换后的重建 |
| 两个不同小方块冒充 A/B | 孔/轴/叶片关键特征与尺寸断言，不只比较哈希 |
| 有角度变量和三角函数，但没有驱动几何 | 多输入实际求值，比较相应几何运动 |
| B 在转，却绕错误中心或连 A 一起转 | 固定件不变、关节轴、相对变换与轨迹断言 |
| 装配姿态看似正确，但插入途中碰撞 | 路径中段检查；明确连续覆盖或采样边界 |
| 剖切后不碰撞，完整零件却碰撞 | 验证使用制造几何，独立检查展示状态不污染制造文件 |
| 数字间隙正值，打印后仍卡死 | 工艺校准、最坏情况尺寸链、实物插拔和转动测试 |

### 3.4 当前哪些验证没有执行

本次没有执行真实配合面测量、路径碰撞、整个角度区间验证、真实 LLM 生成或实物实验。已有测试代码只能支持其明确断言；本次未重跑的历史通过数量不作为当前工作区的通过证明。

可复现实验顺序：冻结合同和工具版本 → 用现有 OpenSCAD 集成测试输出两件 → 保存原始 STL 和哈希 → 独立测量特征 → 对 -45°、0°、45° 和中间自适应样本测量 → 检查轴向路径 → 执行负例 → 经预算确认后打印。当前 `bun run cad:eval:assembly scripts/eval/assembly-fixtures/hinge-contract.json` 是断言比较器入口；未提供观测不能产生几何通过。

## 4. 分层 Evaluation 与独立验证

### 4.1 状态定义和发布规则

| 状态 | 何时使用 | 对必需项的影响 |
|---|---|---|
| PASS | 已执行适用方法，证据与版本匹配，在声明的精度和覆盖范围内满足断言 | 只通过这一条断言 |
| FAIL | 有有效测量或观察明确违反要求 | 阻止相应能力等级通过 |
| SKIP | 冻结合同明确不适用，并保存理由 | 不能替代必需项；必需项 SKIP 阻止通过 |
| ERROR | 已尝试但工具失败、数据损坏、版本不匹配，或精度不足以做判断 | 阻止通过；另计基础设施/证据失败 |
| NOT_RUN | 适用但未执行、能力未实现、缺少材料；粗筛后仍需精查而精查未执行 | 阻止通过；不得计作成功 |

旧报告的 WARN 作为提示保留，不能折算为功能 PASS。整项任务成功要求该目标等级所有适用必需断言通过；不能靠平均分掩盖一个关键失败。报告同时显示证明对象、条件、方法、覆盖和剩余未知项。

### 4.2 六层可执行评估

| 层 | 执行断言与通过条件 | 正例 / 负例 | 数据来源和工具 |
|---|---|---|---|
| L1 需求与意图 | 所有冻结功能、数量、范围、单位、制造条件及未知项均保留；修复前后关键要求无丢失；歧义正确触发确认 | 两件可拆铰链完整保留 / 中文“可拆”丢失、八缸变一缸、mm 当 inch | 原始请求、确认记录、版本差异；独立标注、schema 与需求映射检查、人工盲评 |
| L2 零件与导出 | 每个制造件可选择、非空、完整；实例数、采购件数量与要求一致；文件哈希正确；独立导入恢复位姿；拓扑按制造合同检查 | 一个零件定义复用八次 / 漏件、选择器忽略、错件、同形件误杀、剖切件导出、局部/世界混淆 | 原始 SCAD、逐件 STL、清单；OpenSCAD、独立网格读取和几何测量工具 |
| L3 装配与拆装 | 实际配合尺寸、轴线、间隙及容差栈在界限内；无非允许干涉；装拆路径、顺序及工具空间成立 | 可抽离铰链、可旋出螺纹 / 堵孔、负间隙、闭壳内无法安装、路径中段受阻 | 实际零件网格、冻结配合面和路径；解析尺寸链、窄相几何检查、独立工程师复核 |
| L4 运动 | 实测相对位姿满足关节/闭环约束、自由度、输入输出比例及工作范围；检查非允许碰撞；区分采样与全域证据 | 单缸曲柄连杆、正确行星输出 / 参数闲置、绕错轴、连杆伸长、错误相位、只在采样之间穿透 | 多姿态实际产物/独立位姿测量、解析公式、独立碰撞工具；不能复用生成模型自报坐标当真值 |
| L5 实物装配与功能 | 固定机器、材料、方向、切片及后处理；实测尺寸合格；按说明装拆与功能循环达到预定力、扭矩、寿命门槛 | 独立人员按说明装配成功 / 需要未声明打磨、断裂、卡死、夹具掩盖防脱缺失 | 校准试片、卡尺/量规、力/扭矩测量、视频、实验记录；独立工程师或制造实验室 |
| L6 时间、成本与失败率 | 在冻结资源预算内满足目标等级；完整统计失败、放弃、重试、人工干预、制造废件和缺失账单；达到预设成功率门槛 | 成功且计量齐全 / 只统计完成任务、重试不收费、超时丢记录、价格未知当零 | run ledger、模型调用、渲染日志、用户结果、制造费用；确定性统计和独立复算 |

每层均使用上面的五态。例如：L1 外部标注缺失为 NOT_RUN，标注冲突未裁决为 ERROR；L2 空网格为 FAIL，渲染器崩溃为 ERROR；L3 路径未实现为 NOT_RUN；L4 静态支架无运动要求可 SKIP，但可转动铰链不可；L5 无实物为 NOT_RUN；L6 成本数据缺失时成本断言不得 PASS。

### 4.3 证据的结构与版本

每个断言记录 `requirementId`、层、是否必需、适用条件、期望值、实测值、单位、不确定度、状态、方法、工具版本、覆盖范围、原始证据路径和时间。报告绑定需求版本、源代码哈希、装配规格哈希、每件产物哈希、运行 ID、运行环境及检查器版本。

观测附带哈希只是内容关联，不自动证明真实来源。实际测量应由受控工具执行并保存输入输出；物理证据由实验记录与独立签认支持。修复、手动改源、参数编辑、规格编辑和制造工艺变更，都必须失效受影响的下游结论。

### 4.4 采样、仿真、实测各自能证明什么

- **有限姿态采样：** 证明已测姿态满足指定断言。即使很多帧都通过，也不能排除帧间碰撞。报告样本位置、步长和最小观察间隙。
- **连续区间方法：** 通过保守位移界、自适应区间细分、扫掠体或连续碰撞方法覆盖区间；需要算法适用前提、数值裕量和未解决区间。仅有包围盒粗筛不得宣称复杂配合全域安全。
- **解析计算：** 能证明已定义理想机构的关系与最坏尺寸组合；必须核实实际几何对应模型假设。公式正确不代表生成连杆接到了正确销轴上。
- **仿真：** 结论受材料、摩擦、边界、接触和求解模型约束；未经校准不代替实物。独立求解器的结果也不豁免输入检查。
- **实测：** 证明被测批次、样本和条件的结果；不能推广到所有机器、材料或载荷。记录样本量、离散性、测量误差和失败样本。

### 4.5 冻结集、隐藏集与成功率

建议首版冻结 24 个公开原创任务：单件及静态安装 4、铰链/滑动副 4、螺纹连接 4、齿轮/行星传动 4、曲柄/多缸子装配 4、复杂完整装配 4。每例有需求合同、适用验证层和至少 3 个针对性负例。数量是计划值，冻结前可以调整，不能实验后删难例提高结果。

独立隐藏集建议至少 12 个任务，由不参与生成提示与修复调优的工程师编写；覆盖新尺寸、方向、零件数量、混合连接和此前未见的机构组合。隐藏集及答案不得进入检索、技能、训练样例或调试上下文。若没有独立维护者，只能称保留集，不能声称独立隐藏。

错误注入至少覆盖：遗漏实例、重复整机、错误坐标系、相同合法零件、错单位、孔轴偏移、间隙符号、局部薄片穿透、路径中段阻挡、未使用运动参数、错误比例/相位、修复删件、剖切污染、采购件缺失和旧证据复用。

先用手工原创正确/错误模型测检查器的漏报与误报，再评价 LLM 生成。真实模型实验建议每任务至少 3 次独立运行，固定模型版本、参数、工具预算、修复次数和硬件；随机性不可完全控制时明确记录。公开单次成功率、限预算修复成功率、各层失败率和置信区间，不能只报最好一次。

建议首版发布门槛：冻结安全不变量全部通过；已登记致命负例零误放；合法重复件和坐标变换正例全部通过；隐藏任务目标等级成功率点估计至少 90%，并同时公布区间及样本量。90% 是待基线验证的产品目标，不是当前成绩或统计保证。时间与费用上限在首轮基线和可用预算明确后、正式比较前冻结，不事后移动门槛。

人工盲评至少两人分别查看匿名需求与输出，独立判定需求完整性、操作说明及可理解性；分歧交第三人裁决并保留原判。模型自评可作为诊断信息，不能替代几何和物理真值。

### 4.6 关键结论的独立复核与可推翻条件

| 结论 | 最低支持证据 | 独立复核方式 | 可以推翻的反例 |
|---|---|---|---|
| 保留用户功能意图 | 冻结要求与每次源/规格版本的完整对应 | 不参与生成的评审者盲评 | 必需防脱、数量或工艺条件丢失 |
| 零件可独立导出与重建 | 逐件文件、身份/特征断言、哈希、实例和独立重建 | 另一个查看器/导入器与工程师核对 | 两个文件都是整机；相同零件复用漏实例 |
| 指定姿态可装配 | 实际尺寸、轴线、间隙和干涉证据 | 独立几何工具、解析尺寸链 | 包围盒通过但孔错位或实体穿透 |
| 存在可行装拆路径 | 完整路径与环境、工具、接触和覆盖证明 | 独立路径回放与实物装拆 | 仅起终点可行，中段或工具受阻 |
| 指定范围内运动正确 | 独立测量的关节位置/相对位姿与覆盖证据 | 解析解、另一求解器、工程师复算 | 错轴、错比例、帧间碰撞或连杆变长 |
| 指定工艺下实物可用 | 冻结工艺、实测尺寸、预定功能及循环测试 | 独立制造与盲装、重复批次 | 按说明制造仍卡死、破损或必须额外加工 |
| 当前架构足够支撑目标 | 多类隐藏任务在预算内贯通所需验证层 | 可复现基准与独立报告 | 持续无法提取关键配合特征或满足验证精度/资源预算 |

## 5. 最小改进路径、替代方案与权衡

### 5.1 总体结构

```text
用户功能请求 → 需求确认与冻结合同
                     ↓
          生成/修复完整 SCAD + 候选装配声明
                     ↓
          逐件渲染 + 实例/连接 + 版本化产物
                     ↓
          独立测量 → 分层验证 → 有限修复反馈
                     ↓
        查看/导出/装拆说明/证据与用户验收
                     ↓
        指定工艺制造 → 独立实物实验 → 实物等级
```

SCAD 继续是几何与可编辑参数的来源；合同表达用户期望，清单描述候选零件和连接，独立测量决定是否满足。不能把隐藏 JSON 参数变成与源文件不一致的第二套几何真相。知识、判断策略和修复指导保留在 `skills/`；确定性工具、证据存储与接口在代码里。

### 5.2 里程碑和退出条件

每个阶段按“实现存在 → 局部测试 → 实际工具验证 → 产品端到端 → 独立复核”记录状态；没有证据不能勾选完成。以下“已有基础”只表示上述代码存在。

| 阶段 | 工作与解决的问题 | 必须交付的证据/退出条件 | 主要代价与依赖 |
|---|---|---|---|
| M0 证据基线与反例 | 固定工作区版本；整理原始运行与失败；厘清铰链合同；修正选择器/身份、坐标和导出声明边界 | 样例合同可追溯；伪通过与合法反例可复现；现有全量测试结果留档 | 低至中；后续各阶段依赖。已有比较器与部分样例 |
| M1 意图与装配合同贯通 | 结构化捕获中英文功能意图；稳定零件/实例/连接 ID；功能条件、配合、工艺、公差和接触具备机器可读字段；修订及失效规则 | 正常请求无需用户写 JSON；每次修复保留必需项；过期证据不显示通过；单件流程不回归 | 中；已有 schema/编辑基础，需版本升级和迁移 |
| M2 可交付的零件与装配包 | 本地坐标逐件制造输出；采购件规格；重复实例；独立重建；版本绑定；完整制造与展示分离 | 铰链、重复件和非原点装配可导出并独立还原；负例被正确定位；浏览器完整操作实测 | 中；依赖 M0/M1，已有渲染/包/UI 基础 |
| M3 铰链数字完整闭环 | 实测孔轴和配合；允许接触；插拔路径；运动范围；错误驱动修复 | 铰链 L1–L4 必需项通过；覆盖边界明确；负例无误放；失败可定位到零件/连接/姿态 | 中至高；需独立窄相测量与覆盖方法 |
| M4 单缸曲柄连杆 | 真正的多关节闭环、固定基准、销轴、滑动导向；解析对照与实际几何提取 | 0–360° 位置关系和杆长正确；无非允许碰撞；可装拆；不是摆动几个孤立形状 | 高；依赖 M3 的通用工具，已有公式比较基础不等于完成 |
| M5 螺纹与传动 | 螺距/旋向/多头导程、啮合与侧隙、旋转耦合、齿轮轴线、行星架参考系 | 螺栓螺母、旋盖、齿轮对及行星级分别完成导出、装拆与数字运动；未知强度另列 | 高；可在 M3 后独立推进，与 M4 共享底层 |
| M6 复杂子装配与 V8 | 层级实例、多缸相位、支承和连杆布局、连接件及工具可达性；分批渲染和依赖缓存 | 完整八组运动链及所有要求部件；手驱输入带动全部活塞；制造包完整；装拆顺序可行；独立数字复核 | 高；依赖 M4、所采用连接/传动的 M5 能力 |
| M7 实物功能试验 | 冻结机器/工艺；校准试片；铰链和单缸先行，再做 V8；量化力、扭矩、循环和失效 | 独立人员按说明制造/装拆/操作；所有规定实物功能达标；失败归因和复验保存 | 外部时间与费用；方案可提前写，实验须先明确预算范围 |
| M8 泛化与产品验收 | 冻结/隐藏集、盲评、成本/失败统计、用户结果闭环、文档与回滚 | 达到预设发布门槛；所有声明与证据等级一致；不支持项可见；数据可重放复核 | 持续；不能由单个成功 V8 替代 |

关键依赖：`M0 → M1 → M2 → M3 → M4 → M6`；`M3 → M5`；`M3/M4 → M7 小样 → M6 的实物复核`；M8 贯穿各阶段，最终集中验收。外观和更多模型数量不抢占关键验证工具的优先级。

### 5.3 每个阶段都要贯穿产品与修复

- 交互：自然语言需求摘要、未知条件、零件树、实例高亮、连接选择、装配/爆炸/运动/制造视图，以及定位到姿态的失败信息。高级 JSON 编辑保留为调试入口。
- 生成：支持通用零件和关系表达；先确认关键需求，再生成；需求过复杂时说明资源不足并保留完整要求。
- 渲染：逐件缓存按源码、参数、规格、运行时版本索引；显示几何和制造几何分离；本地与 WASM 运行能力和限制明确显示。
- 修复：输入必须是实测失败、原始日志与不能改变的要求；限制次数和资源；每次产物可追溯、相关检查重跑。
- 验收：用户接受和拒绝有明确入口；接受绑定版本与验收层，不由下载、编辑或 `DELIVERED` 代替。
- 计量：保留 `latencyMs` 的 finally 单次写入、`llmCallCount` 累计增量和统一计数入口；装配导出、几何检查、制造另记阶段耗时，不修改原指标含义。

### 5.4 什么时候需要更大改动

| 选择 | 当前建议 | 代价与升级触发条件 |
|---|---|---|
| 继续 OpenSCAD + 装配合同 + 独立验证 | 首选，从现有代码增量推进 | 网格特征提取、连续碰撞与精度控制较难；若反复无法在预算内验证目标配合，重新评估 |
| 增加解析特征/参数化实体的中间表示 | 在孔、轴、螺纹等关键接口先局部引入 | 要防止声明与生成几何脱节；关键特征应由受控生成过程派生并与产物核对 |
| 增加 B-rep/精确 CAD 后端 | 当拓扑引用、精确曲面、复杂配合或 STEP 交付成为实证瓶颈 | 新依赖与许可需单独决策；参数映射、几何一致性和迁移成本大；不能自动解决意图或真实制造问题 |
| 独立运动/碰撞求解层 | 机构闭环与连续覆盖超出现有简单解析工具时引入 | 求解假设、收敛、接触模型与误差需要验证；不等于实物保证 |
| 独立后台任务/持久化装配模型 | 逐件渲染超过请求预算，或修订/证据规模超过当前复用存储能力时 | 需要可恢复任务、幂等、迁移、取消与版本锁；保留现有 API 兼容适配 |
| 重写整个应用 | 当前没有支持它的证据 | 只有增量路径经反复实验仍无法满足核心要求、迁移收益明确时才讨论 |

功能描述涉及材料变形、弹性卡扣、复杂接触或流体性能时，不能强塞进刚体关节验证器；明确新的验证方法和适用范围。架构升级必须由失败证据驱动，不由展示复杂度驱动。

### 5.5 完成定义

本目标完成需要：已支持范围有自然语言端到端流程；铰链、螺纹/传动、单缸和复杂 V8 关键链路有可重现数字证据；指定实物里程碑由独立测试通过；隐藏集与资源指标达标；每次导出及验收可追溯；未验证/不适用条件对用户可见；没有复制他人代码。

添加 schema、导出几个 STL、通过编译、播放动画、测试检查器或单次做出漂亮 V8，都只是阶段成果。
